# 開発ガイドライン (development-guidelines)

## コーディング規約

- **PEP 8** に準拠。Python >= 3.10。型ヒントを付す（特に公開関数）。
- docstring は機能・引数・**物理的意味と単位**・出典を記述。
- 1 関数 1 責務。Hamiltonian builder は純関数 `H(kvec)->ndarray` とする。

## 命名規則（物理量・軌道）

- 物理量は意味が分かる名前。例: `E_B_s`（B-s オンサイト）, `t_BX_ppsigma`,
  `lambda_SOC`, `Delta_c_over_3`。
- 軌道ラベルは内部で `s, px, py, pz, dxy, dyz, dzx, dx2y2, dz2, sstar` に正規化
  （JSON の `dx2-y2`, `s*` は読み込み時に変換）。
- 数学記号と変数の対応は [glossary.md](glossary.md) に集約。

## 単位の明示

- エネルギー: **eV**、長さ: **Å**。
- パラメータ JSON・docstring・コメントに単位を必ず明記。
- バンドエネルギーは格子定数の数値に依存しない（高対称点を `π/a` 単位で評価）。
  `a` はプロットの k 軸スケールと来歴のために保持。

## 数値計算特有の規約（CLAUDE.md 準拠）

- **浮動小数点の等価比較は禁止**。`==` でなく `np.allclose` / `pytest.approx` を用い、
  許容誤差を明示（例: ギャップ ≤ 10 meV、解析式照合 ≤ 1e-9 eV）。
- **マジックナンバー禁止**。物理定数・パラメータは JSON か名前付き定数に。
- Hermite 性は組み立て後 `H ← (H+H†)/2` で担保し、テストで確認。

## パラメータの取り扱い（ハルシネーション防止）

- **論文記載値をそのまま転記**。改変禁止。誤植が疑われても値は変えず `anomaly` に注記。
- すべてのパラメータに出典（論文・表番号・arXiv ID）を JSON 内に保持。
- 新規パラメータ追加時は、可能なら論文の数値・解析式に対する検証テストを併せて追加。

## テスト規約

- 単体テスト: SK 積分（軸方向手計算・パリティ）、SOC（固有値・規約）。
- **V&V テスト**: 論文の数値（解析式 Eq.9、ギャップ 1.017/1.65/2.75 eV、SO分裂 1.48 eV）を
  許容誤差内で再現することを assert。
- 回帰: パラメータ・実装変更時は `pytest` 全通過を維持。
- 実行: `PYTHONPATH=src pytest -q`（または `pip install -e .` 後 `pytest`）。

## Git 規約

- ブランチ: 既定 `main`。機能追加は作業ブランチ推奨。
- コミットメッセージ: 何を・なぜ。検証結果（再現値）を含めると良い。
- **こまめに commit & push**（進捗を `RESULTS.md` に反映）。
- 大容量データ（PDF・生成 `.npz`）はコミットしない（`.gitignore`）。

## レビュー規約

- ドキュメントは作成後に**批判的に繰り返しレビュー**し、2 回連続で指摘が無ければ承認とする。
- 理論・数値解法の変更は、対応する `docs/` と検証テストを同時に更新する。

## 開発手順（機能追加時）

1. `docs/` への影響（特に理論・数値）を確認。
2. `.steering/YYYYMMDD-タイトル/` に requirements → design → tasklist を作成。
3. 実装と並行して単体テスト・V&V テストを追加。
4. リント・型チェック・`pytest`・バンド図生成で品質確認。
